## 平台简介

Argus 的目标不是只解决“发一个请求”，而是把测试相关的核心资产和执行能力统一到一个平台里：

- 接口资产沉淀
- 真实请求录制与样本归档
- 接口自动化与场景编排
- 测试计划调度
- 性能压测
- Mock 管理
- 环境、变量、数据库、中间件配置
- AI 辅助测试设计

适合的团队包括：

- 测试团队
- 接口自动化团队
- 质量平台团队
- 中后台业务研发团队

## 核心亮点

### 1. 接口资产与真实流量打通

平台支持录制真实请求，并自动或手动关联到接口资产，形成可追溯的实例样本。接口资产不再只是静态目录，而是带有真实请求、真实返回和最新样板的数据资产。

### 2. 实例样本支持三种来源

- 自动关联
- 手动关联
- 手动录入

其中手动来源会锁住后续自动覆盖，适合长期维护关键接口样本。

### 3. 变量体系完整

支持：

- 全局变量
- 接口变量
- 特殊变量
- 出参提取
- 场景链路内变量传递
- 压测内置随机函数

适合登录态接口、多步骤依赖接口和动态数据场景。

### 4. 自动化计划与调度一体化

测试计划和调度器直接打通：

- 新建计划即同步调度任务
- 修改计划即更新调度
- 停用计划即暂停任务
- 执行结果自动进入报告体系

### 5. 性能压测支持链路与预置接口链

支持：

- 单接口压测
- 接口场景压测
- 预置接口链
- 全局请求头注入
- 整次执行一次 / 每并发用户一次 的 setup 语义

适合存在登录态、租户态和步骤依赖的真实业务压测。

### 6. AI 辅助测试设计

平台当前已经落地两类 AI 能力：

- AI 生成接口流程场景
- AI 生成功能测试 XMind 用例

AI 的定位不是聊天入口，而是帮助把需求和业务目标更快转成结构化测试资产。

## 快速开始

### 本地访问地址

默认本地访问地址：

```text
http://localhost:7777
```

### 接口文档地址

FastAPI 默认接口文档地址：

```text
http://localhost:7777/docs
http://localhost:7777/redoc
```

### 前端启动

在 `argus-front` 目录下执行：

```bash
npm run start
```

### 后端启动

在 `argus-end` 目录下执行：

```bash
python ./pity.py
```

后端入口实际通过 Uvicorn 启动 FastAPI 应用。

#### 接口管理

用于管理：

- 服务
- 接口
- 版本
- 实例样本

接口资产支持多种来源接入，除了手工维护外，还支持：

- Swagger / OpenAPI 导入
- YAPI 导入

适合场景：

- 从已有接口文档平台快速初始化接口资产
- 定期同步服务接口定义
- 减少手工维护接口目录的成本

实例样本来源包括：

- 自动关联
- 手动关联
- 手动录入

覆盖规则：

1. 没有样本时，录制命中后自动关联
2. 当前样本为自动关联时，录制可继续自动更新
3. 当前样本为手动关联或手动录入时，录制不再自动覆盖
4. 清除实例数据后，重新恢复自动关联

#### 接口录制

用于采集真实请求并沉淀录制记录。

核心能力：

- 启动/停止录制
- 分组查看 / 平铺查看
- 查看请求详情
- 手动关联实例
- 生成用例

使用接口录制前，需要先开启代理能力。

当前录制代理口径：

- 代理端口：`7778`
- 后端配置：`dev.env` 中 `PROXY_ON=True`

也就是说，录制功能不是默认无条件可用，而是需要先确保：

1. 后端已开启代理开关
2. 本机或目标环境请求已经走到 `7778` 代理端口

只有代理流量真正经过录制代理，平台才能采集到请求并生成录制记录。

自动关联不是简单字符串包含，而是综合：

- Method
- 路径精确匹配
- 路径模板匹配
- 路径后缀分段匹配
- Host / 服务权重

#### Mock 服务

支持按以下维度匹配规则：

- 方法
- 路径后缀
- Query
- Header
- Body
- 优先级

命中后返回自定义状态码、响应头、响应体和延迟。

### 4. 场景测试

#### 接口用例

接口用例是平台最核心的执行单元，通常包含：

- URL
- Method
- 请求头
- 请求体
- 断言
- 出参提取
- 前后置构造器

推荐的场景链路写法：

```text
登录 -> 新增 -> 查询 -> 详情 -> 更新 -> 删除
```

推荐原则：

- 每步只做一件事
- 后续步骤依赖前序步骤时，必须显式提取变量
- 删除前优先通过列表或详情再次确认目标数据
- 最后尽量做清理动作，避免测试数据污染

推荐模板：

新增-查询-删除模板：

```text
步骤1：新增并提取 name / code / id
步骤2：按 name 或 code 查询列表，提取 latestId
步骤3：按 latestId 查询详情并校验
步骤4：按 latestId 删除并断言成功
```

登录-业务操作模板：

```text
步骤1：登录并提取 token / tenantId
步骤2：业务新增，请求头引用 ${token}
步骤3：业务查询，请求头引用 ${token}
步骤4：业务删除或回滚，请求头引用 ${token}
```

## 执行与报告逻辑

### 接口执行顺序

单条接口执行的大致顺序：

1. 读取配置
2. 加载环境与变量
3. 执行前置构造器
4. 渲染 URL / Header / Body
5. 发起请求
6. 提取出参
7. 执行断言
8. 执行后置构造器

### 请求头处理

- Header 可为对象或键值对列表
- 执行前会标准化
- Body 为 JSON 且未声明 `Content-Type` 时，自动补：

```text
application/json; charset=UTF-8
```

### 性能报告为什么只有少量样本

因为请求样本是排查视图，不是全量原始明细。

当前原则：

- 成功样本抽样
- 错误样本优先保留

### 接口样本为什么会锁住自动更新

因为手动来源被视为“人工确认过的标准样本”，平台不会再让后续录制自动覆盖。

## 常见问题

### 1. 变量没生效

优先检查：

- 变量名是否写错
- 前序步骤是否成功提取
- 引用层级是否正确
- 当前执行上下文里是否真的有这个变量

### 2. 录制了接口却没自动关联到接口管理

优先检查：

- Method 是否一致
- 路径是否能命中真实接口路径
- 当前接口是否已有手动样本
- 录制 URL 是否异常

### 3. 性能报告里样本很少

这是采样策略，不代表真实只执行了这么多次请求。真实执行次数看：

- 总请求数
- 成功数
- 失败数

### 4. 执行记录显示完成，但报告内容为空

通常优先检查是否发生了报告收尾写库失败，例如：

- `summary_json` 写入失败
- `errors_json` 过大写入失败

### 5. 接口场景压测里的接口会乱序执行吗

不会。链路内部顺序执行，并发发生在多条链路之间。
